# PRD: 评估-修复迭代循环系统

## 概述

建立一个系统化的评估-修复迭代循环，确保产品质量持续提升。通过自动化评估流程，快速发现、修复问题，形成闭环。

## 目标

- 快速发现功能、集成、用户体验问题
- 修复后立即验证，确保问题真正解决
- 追踪问题状态，避免遗漏
- 量化评估进展

## 用户故事

### US-001: 评估脚本框架
**描述**: 作为开发者，我需要一个可重复运行的评估脚本，能够一键启动服务并执行完整评估流程。

**验收标准**:
- [ ] `start.sh` 能够启动后端(8080)和前端(3000)
- [ ] 服务启动后健康检查通过
- [ ] 评估脚本能够检测服务是否正常运行
- [ ] Typecheck passes

### US-002: 浏览器自动化评估
**描述**: 作为评估者，我需要使用 browser-use skill 自动遍历产品核心流程，验证功能完整性。

**验收标准**:
- [ ] 能够上传一本书籍(EPub/PDF)
- [ ] 能够解析书籍(如果未解析)
- [ ] 能够提取概念(如果已解析)
- [ ] 能够打开书籍详情页查看PDF/EPUB阅读器
- [ ] 能够查看概念图谱
- [ ] Typecheck passes
- [ ] Verify in browser using browser-use skill

### US-003: 问题分类与定级
**描述**: 作为评估者，我需要对发现的问题进行严重程度分类，确保优先修复关键问题。

**验收标准**:
- [ ] BLOCKING - 阻塞性问题，无法正常使用
- [ ] HIGH - 严重问题，影响核心功能
- [ ] MEDIUM - 一般问题，不影响主要流程
- [ ] SUGGESTION - 建议改进
- [ ] 每个问题有明确的文件位置和代码行号
- [ ] Typecheck passes

### US-004: 问题追踪与修复
**描述**: 作为开发者，我需要追踪每个问题的修复状态，确保所有 BLOCKING 问题被及时解决。

**验收标准**:
- [ ] 创建问题追踪列表(Task)
- [ ] BLOCKING 问题标记为最高优先级
- [ ] 修复后更新问题状态为 completed
- [ ] Typecheck passes

### US-005: 修复验证评估
**描述**: 作为评估者，我需要在问题修复后重新运行评估，确认问题已解决且无引入新问题。

**验收标准**:
- [ ] 重新执行完整浏览器遍历流程
- [ ] 确认之前的 BLOCKING 问题已修复
- [ ] 检查是否有新引入的问题
- [ ] 更新评估报告
- [ ] Typecheck passes
- [ ] Verify in browser using browser-use skill

### US-006: 评估报告生成
**描述**: 作为项目管理者，我需要生成评估报告，记录问题状态和改进进展。

**验收标准**:
- [ ] 报告包含：问题列表、修复状态、优先顺序
- [ ] 报告保存到 `tasks/evaluation-report-YYYY-MM-DD.md`
- [ ] 包含修复前后的对比
- [ ] Typecheck passes

### US-007: 迭代循环直到稳定
**描述**: 作为项目团队，我们需要重复"评估-修复"循环，直到没有 BLOCKING 问题。

**验收标准**:
- [ ] 循环执行直到所有 BLOCKING 问题被修复
- [ ] 每次迭代生成新的评估报告
- [ ] MEDIUM/SUGGESTION 问题可延后处理
- [ ] 记录迭代次数和修复耗时
- [ ] Typecheck passes

## 非目标

- 不修复外部依赖问题（如 LM Studio 未运行）
- 不修复测试数据问题（如损坏的 PDF）
- 不做性能优化评估

## 技术考虑

- 使用 `start.sh` 启动服务
- 使用 `browser-use` skill 进行浏览器自动化
- 评估报告保存到 `tasks/` 目录
- 问题追踪使用 Task 工具

## 成功指标

- 所有 BLOCKING 问题在 24 小时内修复
- 每次迭代后 BLOCKING 问题数量递减
- 评估循环可在 30 分钟内完成
